# 2026-10-28 分组 / 标签 / 批处理修复方案

本轮针对正式版使用中暴露的七个问题，原则是：**分组是层级，标签是论文属性，批处理按快照执行**；三者互不覆盖，旧数据可无损迁移。

## 1. 行内只保留删除

- 问题：条目行右侧同时有文件夹、铅笔、齿轮、垃圾桶，鼠标悬停时挤在一起，误点。
- 方案：行内只保留垃圾桶；改名/分组/设置分别放到详情页与顶部设置入口。
- 代码：`features/library/LibraryList.tsx` 行渲染只留 `item-delete`；`ItemDetailPanel.tsx` 提供标题编辑与分组输入。
- 取舍：不再提供行内“一键移动分组”，避免与双击进详情冲突；移动已有论文统一走详情页。

## 2. 标签系统（与分组独立）

- 问题：论文进入分组后，领域标签被组名替换，分组承担了“分类 + 标签”两种职责。
- 方案：新增 `tags(kind,color)` 与 `item_tags` 多对多；分组只存 `items.group_name` 路径。文库行显示原始领域标签；详情页可增删自由标签；文库顶部可按标签筛选；批处理可按标签取并集。
- 代码：`db/schema.sql`、`db/migrate.ts`、`services/item-tags.ts`、`ipc/library.ts`（`listTags/setItemTags`）、`shared/item-tags.ts`、`LibraryList.tsx`、`ItemDetailPanel.tsx`、`BatchPanel.tsx`。
- 边界：标签是自由文本，不做自动同义词合并；领域识别产生的标签保留原样。

## 3. 分组介绍与编辑

- 问题：分组只有名字，无法记录这个方向“在做什么”。
- 方案：`library_groups` 增加 `description/date_modified`；点击分组时在列表下方显示介绍与「编辑分组信息」；编辑名称会同步迁移该组及所有子组的路径。
- 代码：`services/library-groups.ts::getLibraryGroup/updateLibraryGroup`、`ipc/library.ts`、`LibraryList.tsx` 分组信息区与弹窗、`shared/library-groups.ts`。
- 迁移：旧库只加列；旧扁平路径 `A/B` 若缺少 `A` 行，启动时补齐祖先节点，避免树断链。

## 4. 已有论文移动到新分组

- 问题：分组只能靠导入时指定，已有论文没有入口。
- 方案：详情页「分组」输入框接受 `父/子/孙` 完整路径，保存时自动建缺失层级；留空移出分组。
- 代码：`ItemDetailPanel.tsx` 的 `detail-group-input`/`detail-group-save`，调用 `library.setGroup`；`ensureGroupPath` 负责建父级。

## 5. 一个分组可继续导入（修复“4 篇后不能传”）

- 根因：旧实现由渲染层在导入后按“新 id 差集”补归组；连续上传时差集与刷新竞争，越传越容易漏，表现为传几篇后“不动了”。
- 方案：把 `group` 参数贯穿 `library.importPdf/importPdfs/importFolder/importUrl(s)`，在主进程导入事务内直接写入 `items.group_name`，不再依赖渲染层补刀。
- 代码：`ipc/library.ts`、`services/files.ts::importPdfFromPath`、`shared/api.ts`、`preload/index.ts`、`App.tsx` 导入回调、`LibraryList.tsx` 当前分组。
- 验证：同一分组连续导入 5 篇均成功归组。

## 6. 批处理按分组 / 按标签

- 方案：`BatchScope` 增加 `tag`；分组仍按完整路径含全部子组；标签按命中论文并集。目标在 `batch.create` 时解析为 `batch_items` 快照，之后改组/改标签不影响已在跑的作业。
- 代码：`services/batch/queue.ts::resolveItems`、`services/batch/validate.ts`、`shared/types.ts`、`BatchPanel.tsx` 范围选择与分组/标签选择器。
- 边界：空分组或无标签时给出可读提示，不创建空作业。

## 7. 批量翻译/拆解全部失败

- 现象：作业一开始就失败，错误为 `HTTP 400 Model is unavailable`。
- 根因：设置里保存的是展示名 `DeepSeek V4.1 Flash`，而 API 需要模型 ID；网关对展示名返回 400（对旧 `deepseek-flash` 返回 410，并给出 replacement）。
- 方案：`services/settings.ts::normalizeModelId` 把已知展示名/旧别名归一成 `deepseek-v4.1-flash` 等 ID；批处理创建前仍走同一 provider 配置解析。
- 代码：`services/settings.ts`、`features/settings/SettingsDialog.tsx`（保存时校验空模型）；README 增加模型名说明。
- 说明：Key 仍由 `safeStorage` 解密后只在主进程使用；本次未更换用户 Key。

## 验证

- `npm run typecheck`、`test:unit`、`test:coords`、`test:py`、`smoke`、`build`、完整 `test:e2e`。
- 手工验证：多级分组悬停、详情页移动分组、分组介绍编辑、连续导入 5 篇、标签筛选与批处理按标签。
- 旧库迁移：启动时建表/加列/补祖先，不删除旧分组数据。
